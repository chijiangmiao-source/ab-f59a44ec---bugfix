# 雷达脉冲序列审计（海岸监测站）

海岸监测站把多部雷达的脉冲时刻混入同一通道。本工具帮助复核员**离线**地把混合时刻重新分组为可重算的发射序列：纯前端单页应用（TypeScript + React + Vite），不依赖任何业务后端或在线服务，全部计算在本机浏览器内完成。

## 功能

- **可编辑输入**：脉冲时刻（6–28 个严格递增的非负整数，微秒）、候选重频（1–6 个互异正整数，微秒）、漏发上限（0–2）。
- **审计目标**：在每个脉冲恰属一条序列、每条序列至少两个脉冲、相邻时差为同一重频整数倍且不超漏发限制的约束下——
  1. 先**最小化序列数**；
  2. 再**最小化漏发总数**；
  3. 判断两项目标均最优时**是否存在不同分组**；
  4. 给出**规范解**：各序列按（首脉冲时刻、重频、脉冲下标）排序后整体字典序最小者。
- **时间轴视图**：总览 + 每条序列一条泳道，脉冲按时刻定位、按序列着色，漏发位置以红色虚线圈标出期望时刻。
- **无解反馈**：明确提示不存在全覆盖分组，并展示每个脉冲可参与的候选连接数（出向/入向）。
- **草稿保留**：非法输入不会被清空，所有问题一次性汇总提示。
- **可中断计算**：求解在 Web Worker 中进行，计算期间页面可继续操作；再次发起审计会终止旧计算，旧结果不会覆盖新审计。
- **结果导出**：审计结果（含输入回显）可导出 JSON / 复制到剪贴板，便于离线复核重算。

## 本地开发

```bash
npm install
npm run dev      # 开发服务器
npm test         # 求解器单元测试（含暴力枚举对照）
npm run build    # 类型检查并产出 dist/
```

## Docker 发布

```bash
# 启动页面（默认宿主机端口 8080）
docker compose up --build web

# 自定义宿主机端口（例如 9090）
APP_PORT=9090 docker compose up --build web

# 健康检查
curl http://localhost:8080/healthz   # -> ok
```

- `web` 服务：多阶段构建，nginx 托管静态页面，容器内 80 端口；宿主机端口通过环境变量 `APP_PORT` 配置（默认 8080）。
- 健康检查：Dockerfile `HEALTHCHECK` 与 Compose `healthcheck` 均探测 `/healthz`。

## 验收（verify 服务）

```bash
docker compose up --build --exit-code-from verify verify
```

`verify` 服务会：等待 `web` 健康 → 校验首页、挂载点、静态资源与 SPA 回退 → 运行求解器验收测试（vitest）。全部通过时容器以退出码 0 结束，`--exit-code-from verify` 会把该退出码作为命令结果。

## 求解模型（简述）

把每个脉冲看作 DAG 顶点；若 `t[j] − t[i] = k × 重频`（`1 ≤ k ≤ 漏发上限+1`），则存在带重频标签与漏发代价 `k−1` 的候选边 `i → j`。合法分组 = 顶点不相交、同路径同重频、无孤立顶点的路径覆盖；序列数 = 脉冲数 − 边数。求解器按顶点顺序做分支限界深度搜索（边上界 / 代价下界 / 前向检查剪枝），先最大化边数再最小化代价；随后以计数搜索判断是否多解，并用"逐段贪心 + 可行性预言机"构造字典序最小的规范解。`src/solver/solve.test.ts` 中以暴力枚举对大量随机用例做了交叉验证。

## 目录结构

```
src/
  solver/       纯 TS 求解器与输入校验（无框架依赖，可独立测试）
  worker/       Web Worker：后台执行审计，保证页面可操作
  components/   输入面板、时间轴、结果视图、无解视图
verify/run.mjs  验收服务入口
Dockerfile      多阶段：build → web（nginx）/ verify（验收）
docker-compose.yml
```
